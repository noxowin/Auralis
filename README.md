# Auralis · 多设备同步播放

把电脑正在播放的声音，同时送到多个输出设备：几副有线耳机、蓝牙耳机、USB 声卡、显示器/电视的 HDMI 音箱都可以一起响。

不需要安装虚拟声卡驱动，也不需要修改系统默认设备。

## 怎么用

1. 双击 `AudioShare.exe`（Windows 10 1809 及以上，免安装）。
2. 在「输出设备」列表里，把**所有**想出声的设备的开关打开（包括你原来就在用的那副耳机）。
3. 点击右上角「开始共享」。

### 对齐模式（默认打开，推荐）

开始共享时，程序会把系统默认播放设备临时换成一个闲置的设备（优先选显示器/HDMI 音频或电脑自带扬声器），并把它静音。这个设备叫「中转设备」，只用来接住系统声音，本身不出声。所有打开的设备都播放复制出来的同一份声音，所以可以用延迟滑块完全对齐。

- 停止共享、退出程序、注销或关机时，默认设备和静音状态会自动改回去。
- 即使程序崩溃或被强制结束，下次打开时也会先把设置恢复。
- 中转设备默认自动选择，也可以在下拉框里指定。如果所有设备都打开了、没有闲置设备，程序会提示你关掉一个，或者改用直接模式。
- 少数老程序不会跟着默认设备切换。如果某个程序没声音，重新打开那个程序即可。

### 直接模式

关闭「对齐模式」后，系统默认设备照常直接播放，其他设备播放复制的声音。不会改动任何系统设置，但默认设备总会比其他设备早一点，延迟滑块只能让其他设备更晚，无法让它们追上默认设备。

### 自动校准延迟

蓝牙耳机通常比有线耳机慢 150～250 ms。不想手动拖滑块的话：

1. 先开始共享，并打开要对齐的设备（至少两台，需要对齐模式）。
2. 暂停正在播放的视频，把所有耳机放到电脑麦克风旁边。
3. 点「输出设备」右边的「自动校准」，再点「开始校准」，保持安静大约 10 秒。

每台设备会轮流发出几声"嘀"，程序根据麦克风听到的时间差，自动调好每台设备的延迟滑块。不要选蓝牙耳机上的麦克风，打开它会让蓝牙耳机切到音质很差的通话模式。

### 自动防杂音

如果某台设备因为缓冲不够出现断续，程序会自动把「缓冲」加 10 ms，并在顶部提示。所有设备一起加，所以已经调好的对齐不会被打乱。系统本身暂停播放造成的停顿不会被误判。

### 单声道

每台设备卡片里都有「单声道」开关。打开后左右声道会合并，适合只戴一只耳机，或者两个人各戴一只的情况，不会漏掉只在另一边声道里的声音。

### 方案

调好一套设置后（哪些设备打开、音量、延迟、单声道），点顶部的「保存当前」存成方案，例如"蓝牙 + 有线看电影"。以后在下拉框里选它，就会一键切换回来。

### 托盘和开机自启

- 关掉窗口不会停止共享，程序会缩到右下角托盘。左键点托盘图标打开窗口，右键可以开始/停止共享或退出。
- 在窗口底部或托盘菜单里打开「开机自动启动」后，开机时程序会直接在托盘里运行；如果上次退出时正在共享，会自动接着共享。
- 程序只允许运行一个。再次双击 exe 会打开已经在运行的那个窗口。

### 其他

- 每个设备都有自己的音量滑块。
- **延迟对齐**：蓝牙耳机通常比有线耳机慢 150～300 ms。如果听到"回声"，就给**更快的那台**（通常是有线设备）把延迟滑块往右拖，直到两边听起来一致。
- 底部「缓冲」：如果出现咔哒声、断续，就调大一点；想要更跟手，就调小一点。
- 设备拔掉再插回、蓝牙重连后会自动恢复播放。设置会自动保存，下次打开时恢复。

## 工作原理

```
应用播放的声音 ──► 系统默认设备（照常播放）
                       │  WASAPI loopback 旁路捕获
                       ▼
                 AudioRouter（复制分发）
          ┌────────────┼────────────┐
          ▼            ▼            ▼
   声道转换+缓冲   声道转换+缓冲   声道转换+缓冲
   自适应重采样   自适应重采样   自适应重采样
          ▼            ▼            ▼
      耳机 A        蓝牙耳机       音箱
```

- **捕获**：WASAPI loopback 是 Windows 自带的接口，可以读到某个输出设备正在播放的混音（设备被静音时也能读到）。
- **切换默认设备**：Windows 没有公开这个 API，这里用的是系统声音设置自己用的 IPolicyConfig 接口，SoundSwitch、EarTrumpet 等工具也用它。
- **时钟漂移补偿**：每块声卡都有自己的晶振，标称 48 kHz 的设备实际可能快或慢几百 ppm。不处理的话，几分钟后就会断音，或者延迟越来越大。`AdaptiveResampler` 盯着每个设备的缓冲水位，用 PI 控制器把播放速度在 ±0.5% 范围内微调（人耳听不出来），同时完成 44.1k/48k/96k 之间的采样率转换（三次插值）。
- **声道转换**：5.1/7.1 下混到立体声，立体声转单声道（蓝牙免提模式）等。
- **自动校准**：校准时所有设备暂时只播放静音和测试音（60 ms 的 800 Hz→5 kHz 扫频），测试音插在同一条采集时间轴的指定位置上。麦克风录音与测试音做归一化互相关，找出每次到达的时刻，每台设备重复 3 轮取中位数。
- **杂音识别**：设备读空时，如果读空前采集端刚送过数据、读空后又很快有新数据，就是缓冲不够；如果之后很久都没有新数据，就是系统本身停止了播放。

## 项目结构

| 路径 | 内容 |
|---|---|
| `src/AudioShare.Core` | 与平台无关的音频处理：环形缓冲、声道转换、自适应重采样 |
| `src/AudioShare.App` | WPF 界面、WASAPI 捕获与播放、设备插拔监听 |
| `tests/AudioShare.Sim` | 离线模拟：时钟漂移补偿、杂音识别、自动校准的测量精度 |

## 从源码构建

需要 .NET 8 SDK（Windows 上装 Visual Studio 2022 或单独安装 SDK 都可以）。

```powershell
dotnet run --project tests/AudioShare.Sim          # 运行模拟测试
dotnet run --project src/AudioShare.App            # 运行程序
dotnet publish src/AudioShare.App -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

## 已知限制

- 对齐模式需要至少一个闲置的播放设备来当中转。大多数电脑都有（显示器/HDMI 音频、自带扬声器）。
- 以"独占模式"播放的程序（少数专业音频软件）捕获不到。
- 蓝牙耳机本身的延迟无法消除，只能通过给其他设备加延迟来对齐。
- 蓝牙耳机如果处于"免提/Hands-Free"模式（同时被当作麦克风使用），音质会明显变差，这是蓝牙协议的限制。
